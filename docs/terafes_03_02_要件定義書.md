# 要件定義書　ゆめかわ★ウイルス・ぽっぷ

| 項目 | 内容 |
|---|---|
| チーム | 情報処理科2年 3班（松井・岡野・中山） |
| 版・作成日 | 第1版（ドラフト）　2026年10月5日 |
| 参照資料 | 学園祭展示企画書、サンプルアプリ（DOM版） |

## 1. 目的と範囲

- **目的**：学園祭で展示するリズムゲームを、授業の実習時間内（3名×各4時間）で実装できる最小限の機能で作る。
- **作るもの**：2つのコースで遊べ、ランキングまで動く、完全ローカルのブラウザゲーム。
- **作らないもの**：5章を参照。

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 開発言語 | HTML5、CSS3、JavaScript |
| 描画方式 | DOM + CSS（企画書のCanvas APIから変更） |
| 使用しないもの | フレームワーク、外部ライブラリ、画像・音声ファイル、サーバー、データベース |
| 使用する機能 | キー入力（KeyboardEvent）、Web Audio API、LocalStorage |
| 実行方法 | 展示PCで index.html を開くだけ（完全ローカル） |
| 操作 | キーボードの1〜4キー（テンキーは使わない。上段の数字キーを想定） |
| 工数 | 3名×各4時間（テストは別枠） |

## 3. 機能要件

◎＝必須　○＝できれば（必須がすべて動いてから着手する）

| ID | 機能 | 要件 | 優先度 |
|---|---|---|---|
| F-01 | コース選択 | タイトル画面で「初級：甘口ぽっぷ編（2レーン・60秒）」「上級：激辛フィーバー編（4レーン・90秒）」を選んで開始する | ◎ |
| F-02 | ノーツ落下 | ウイルスが画面上部から判定ラインに向かって落ちてくる | ◎ |
| F-03 | キー判定 | 1〜4キーでタイミングを判定し、「大優勝！」「神！」「超かわよ！」「ざんねん…（ミス）」を表示する | ◎ |
| F-04 | スコア・コンボ・HP | スコア、コンボ数、サーバーHP（ハートメーター）を表示する。ミスでHPが減る | ◎ |
| F-05 | ゲーム終了 | プレイ時間が過ぎるか、HPが0になったら終了する | ◎ |
| F-06 | リザルト | 防衛率、ランク、スコアを認定証風に、全ランクで表示する。「もう一回」「タイトルへ」を選べる | ◎ |
| F-07 | ランキング | スコア上位10件をLocalStorageに保存し、リザルトに表示する | ◎ |
| F-08 | キャラクター | ピンク・ミントグリーン・イエローの3種のウイルスを表示する | ◎ |
| F-09 | BGM・効果音 | BGMと、撃退時の効果音を鳴らす | ◎ |
| O-01 | ヒット演出 | 撃退時に粒がはじけるアニメーション | ○ |
| O-02 | キャラの特徴 | トゲ、針付き帽子、群れなど、企画書どおりの見た目 | ○ |
| O-03 | ランキングのリセット | スタッフ用に、全記録を消せる | ○ |

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| ブラウザ | Chrome |
| 解像度 | 横1920px（画面比率は16:9を想定。ゲーム画面は余白が出ないよう、画面に合わせて拡大縮小する） |
| 性能 | プレイ中にカクつかず、30fps以上で動く |
| 音と判定の同期 | 判定の基準時刻は、Web Audioの時計を使う |
| 堅牢性 | LocalStorageが使えなくても、ゲームは最後まで動く |

## 5. 対象外

- 一時停止、設定画面、音量調整
- ユーザー名の入力（ランキングは名前なしで自動登録）
- スマホ・タブレット対応
- サーバー通信、他のPCとのランキング共有

## 6. 未決事項

- 展示PCの画面の縦サイズ（1080を想定。16:9以外の場合は余白が出る）
