## 1. 重点レビュー項目

- JavaScript（保守性・コード品質）
  1. 変数名・関数名が、処理内容を表す名前になっているか
  2. 重なっている処理や、使っていない処理がないか
  3. 例外（エラー）のときに、止まらずに動くか
  4. 仕様書と合っていない所がないか
- HTML・CSS（保守性・アクセシビリティ）
  1. 使っていない指定や、重なっている指定がないか
  2. ボタンや画像に、読み上げ用の名前・説明があるか
  3. 仕様書と合っていない所がないか

### 例外（エラー）のときに止まらずに動くか（JavaScript の 3）

- 保存（ranking.js）：try / catch で囲んであり、テスト（T-084〜T-086）でも止まらなかった。
- 豆知識（screens.js）：`TIPS` がなくても止まらない。
- 音（audio.js）：AudioContext が作れないブラウザでは止まるが、展示は Chrome なので問題なし。

## 4. よかった点

- 名前・記録の表示はすべて `textContent` で入れていて、HTMLとして解釈されない（意地悪テスト T-010・T-080 でも確認）。
- 担当ごとにファイルを分け、ファイルをまたぐ呼び出しを仕様書10.1に決めてある。そのため、3人で同時に作業してもぶつからなかった。
- 時計を Web Audio の時計1つにまとめているので、音と判定がずれない（仕様書9章）。
- 曲データは仕様書5.1・8.1と全部合っていた（6曲とも、`chords` と `chart` の拍の合計が同じ）。
- 豆知識は IPA のページを出典として書いてあり、10個とも40文字前後に収まっている。
- おうちのボタンに読み上げ用の名前（`aria-label="タイトルへ"`）があり、マークの絵は読み上げない（`aria-hidden`）ようにしてある。
- 「あそぶ」の透明ボタンは、文字を消さずに見えなくして、読み上げ用に残してある。
- result.css に、動きが苦手な人向けにアニメーションを止める指定がある（`prefers-reduced-motion`）。
- フォントを同梱していて、ネットなしでも同じ見た目になる。
- `// ★` のコメントが、中学生にも分かる言葉でほぼ全行に付いている。色・ルール・使える id も、各ファイルの先頭のコメントにまとめてあり、担当外の人にも分かる。
