## 2. スケジュール

第3回（10/9 金）の前に、次の4つを終わらせた（10/8 作成）。

1. 要件定義書の未決事項の決定。決まった内容を要件定義書に反映する
2. 要件定義書に従って、仕様書を再作成する（各画面の名前、ファイルの持ち主、部品のつなぎ目を決める）
3. 画面モックアップを作り、リポジトリの `main` に入れる（松井さん。4つの画面の骨組みと、空のファイル）
4. 仕様書どおりに動く見本（`sample/`）を作り、`main` に入れる（読むだけで、直さない）

- **3回目のはじめ**：全員で、仕様書の**つなぎ目（8章のデータの形、10章の関数の名前）**を確認して固定する。以後、変えるときはコミットの前に相談する。
- **3回目の最初の15分**：全員で、リポジトリの取得（モックアップが入った `main`）、ブランチの作成、プッシュ、プルリクエストまでを一度やってみる（手順は `Git使い方.txt`）。Gitに不慣れな人は、ここで慣れておく。
- **3回目の進め方**：モックアップは10/8に作成済み。各自、見本のソース地図で自分の担当の場所を読んでから始める。中山さんはモックアップに実装を載せ、岡野さんは認定証の見た目から始める。
- **動作確認の流れ（3回目）**：中山さんが、曲が1つ遊べる状態をプルリクエストで送る → 松井さんが確認してマージ → 岡野さんが `main` をプルして遊ぶ → 気づいたことを `docs/test.md` に記録して、中山さんに伝える。
- **追加機能**は、必須機能の統合が終わってから着手する。必須機能が間に合わない場合は、追加機能を後回しにする。
