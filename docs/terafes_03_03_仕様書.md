## 1. 位置づけ

要件定義書の各要件（F-01〜F-10、O-01〜O-07、非機能要件）を、画面・動作・データの仕様として具体的に書いたものである。要件との対応は11章にまとめた。

- 数値・計算式・データの形・関数の名前は、**この仕様書どおりに作る**（AIに実装を任せるときも、この仕様書を渡す）。
- 音とリズム（7章）は、あえて詳しく書かない。サンプルを出発点にして、遊びながら調整する。
- 見た目（色・大きさ・配置の細部）は、画面モックアップで決める。この仕様書には、必要な要素だけを書く。
- 動作の細部で迷ったときは、サンプルの動きを基準にする。

## 3. 画面仕様

### 3.1 画面遷移

画面の名前は、**タイトル画面、セレクト画面、プレイ画面、リザルト画面**（カタカナで統一する）。

画面遷移図・画面一覧・遷移一覧は、別紙「画面遷移図」（この仕様書と同じ回の番号のもの）を参照する。下の図は、その要約である（下の表）。

| 画面 | 操作 → 移る先 |
| --- | --- |
| タイトル | Enter／あそぶ → セレクト |
| セレクト | 曲を決める → プレイ ／ Esc／タイトルへ → タイトル |
| プレイ | 終了（曲の終わり、HP0） → リザルト ／ Esc → セレクト |

- 背景は全画面で共通：パステルのグラデーションに青い格子線を重ね、ハートと星がゆっくり漂う（`#fl`）。

## 4. 入力仕様

| 画面 | 操作 | 動作 |
| --- | --- | --- |
| タイトル | Enter／あそぶボタン | セレクト画面へ |
| タイトル | リセットボタン | 確認ダイアログの後、全曲のランキングを消す |
| セレクト | ← →（↑ ↓も可） | 選択中の曲を切り替える（端は反対側へ回り込む） |
| セレクト | Enter／カードのクリック | 選択中の曲（クリックした曲）を開始 |
| セレクト | 数字キー 1〜（曲の数） | その番号の曲をすぐ開始 |
| セレクト | Esc／タイトルへボタン | タイトルへ |
| プレイ | 2レーン：F・J ／ 4レーン：D・F・J・K | 左から順に対応するレーンを叩く |
| プレイ | 数字キー 1〜4 | 左から順にレーン1〜4を叩く（レーン数を超える番号は無効） |
| プレイ | Esc | 中断してセレクト画面へ |
| リザルト（名前の入力中） | 文字の入力 | 名前を入れる（6文字まで。日本語入力も可）。D・F・J・K や数字キーは、文字として入るだけ |
| リザルト（名前の入力中） | Enter | 名前を決める。空のときは「ななし」。日本語入力の変換を決めるEnter（`isComposing` が `true`）では決めない |
| リザルト（名前の入力中） | Esc | 入力をやめて「ななし」で決める |
| リザルト | Enter／Esc | もう一回／セレクト画面へ（名前を決めた後） |
| リザルト | タイトルへボタン | タイトルへ（名前を決めた後） |

- 数字キーは上段（`Digit1〜4`）だけを受け付ける。テンキー（`Numpad`）は受け付けない。
- キーの押しっぱなし（リピート）は無視する。
- 一時停止はない。

## 5. ゲーム仕様

### 5.1 曲の設定

| 項目 | きらきら星 | ジングルベル | 天国と地獄 |
| --- | --- | --- | --- |
| 星／ラベル | ★1／やさしい | ★3／ふつう | ★5／げきむず |
| レーン／キー | 2レーン／F・J | 4レーン／D・F・J・K | 4レーン／D・F・J・K |
| BPM | 100 | 120 | 140 |
| 落下時間（上端→判定リング） | 2.2秒 | 1.6秒 | 1.4秒 |
| 長さの目安 | 約29秒 | 約40秒 | 約42秒 |
| 同時に落ちるウイルス | なし | なし | 一部にあり（5.2） |

- 難易度は、レーン数・ノーツの数（密度）・落下時間の組み合わせで決まる。数値は、遊んで調整する。

### 5.2 譜面の作成

曲データの `chart`（8.1）から、ノーツの一覧を作る。同じ曲は毎回同じ譜面になる。

1. 1拍の長さ ＝ 60 ÷ BPM（秒）。
2. 準備時間 `lead` ＝ （落下時間＋0.3秒）を1拍単位で切り上げた長さ。
3. 曲データを先頭から読み、休符（`R`）以外の音を1つずつノーツにする。到達時刻 ＝ `lead` ＋ （それまでの拍の合計）× 1拍の長さ。休符は時間だけ進める。
4. **レーン**：曲に出てくる音の高さを低い順に並べ、「何番目の音か」で決める。レーン ＝ 切り捨て（順位 × レーン数 ÷ 音の種類数）。低い音が左、高い音が右。
5. **ウイルスの種類**：レーン番号を3で割った余り（0：ランサム、1：フィッシング、2：DDoS）。
6. **同時に落ちるウイルス**：`chart` で `+` でつないだ音（8.1）は、同じ到達時刻のノーツにする。同じレーンになったときは、片方を隣のレーンへずらす。
7. **音の高さ**：音名から決める（A4 ＝ 440Hz を基準にした平均律）。

### 5.3 判定

基準時刻は Web Audio の時計（`AudioContext.currentTime`）を使う。曲の開始時刻 `t0` からの経過時間を `t` とする。押したレーンの未処理ノーツのうち、到達時刻との差が最も小さいものを対象にする。

| 判定 | タイミング差 | 基本点 | 表示色 |
| --- | --- | --- | --- |
| 大優勝！ | 0.06秒未満 | 300 | ピンク `#ff4fa3` |
| 神！ | 0.12秒未満 | 200 | 水色 `#3bb8ff` |
| 超かわよ！ | 0.2秒以内 | 100 | 紫 `#9a6bff` |
| ざんねん…（ミス） | 到達から0.2秒過ぎても未入力 | 0 | 灰紫 `#8a7bb0` |

0.2秒の範囲外での空打ちにペナルティはない（何も起きない）。

### 5.4 ウイルスの動き

- 到達時刻の「落下時間×1.15」前に出現させる。
- 縦位置 ＝ 500 − （到達時刻 − 現在の `t`）÷ 落下時間 × 530。到達時刻に判定リング（y=500）へ重なる。
- 撃退またはミスで画面から消す。

### 5.5 スコア・コンボ・HP

| 項目 | 仕様 |
| --- | --- |
| スコア | 基本点 ＋ min(コンボ数, 50) × 2 を加算 |
| コンボ | 撃退で＋1、ミスで0に戻る。最大コンボを記録する |
| サーバーHP | 初期値10。ミス1回で−1 |

### 5.6 ゲーム終了

次のどちらかで終了し、リザルト画面へ移る。

- 終了時刻（`lead` ＋ 曲の長さ ＋ 1秒）を過ぎた。
- サーバーHPが0になった。

### 5.7 防衛率とランク

防衛率 ＝ 撃退したノーツ数 ÷ 全ノーツ数 × 100（四捨五入）。HPが0で途中終了した場合も、分母は全ノーツ数のままとする。

| ランク | 防衛率 | コメント |
| --- | --- | --- |
| S | 95%以上 | 超大優勝★ |
| A | 85%以上 | 大優勝！ |
| B | 70%以上 | 神！ |
| C | 70%未満 | まだまだかわいい |

## 6. キャラクター仕様

キャラは**全画面で同じ見た目**にする（タイトル画面のキャラが基準）。HTMLの形と見た目は `chara.css` にまとめ、画面ごとに大きさ（倍率 `--s`）だけを変える。

| 種類 | 名前 | 色 | 見た目の特徴 | セリフ（タイトル画面） |
| --- | --- | --- | --- | --- |
| 0 | ぷにぷにランサムちゃん | ピンク | 星形のトゲが後ろで回転、頭に南京錠 | 「データを人質にとっちゃうぞ♡」 |
| 1 | てくてくフィッシング | ミントグリーン | 帽子と釣り針 | 「ニセのリンクで釣っちゃうよ〜」 |
| 2 | パニックDDoS | イエロー | 一回り小さい顔、触角2本、「>\_\<」の表情 | 「みんなで押しかけるよ！」 |

- どのキャラも上下にゆらゆら揺れる。
- フィッシングには、帽子をサンタの帽子にした見た目（`.santa`）もある。セレクト画面のジングルベルのカードと、ジングルベルのプレイ中に落ちてくるフィッシングで使う。
- 使う場所と大きさ：タイトル画面（等倍、名前とセリフつき）、セレクト画面のカード（約0.7倍）、プレイ画面のウイルス（約0.6倍、名前なし）、認定証の飾り（約0.45倍）。
- プレイ画面では、`view.js` の `mkVirus` が、`chara.css` の先頭に書いたHTMLの形でウイルスを作る。

## 7. サウンド仕様

すべて Web Audio API で合成する（音声ファイルなし）。具体的な音色・音量・パターンは、`index_3songs.html` を出発点にして、**開発中に遊びながら調整する**（この仕様書では細かく決めない）。

| 項目 | 仕様 |
| --- | --- |
| BGM | ドラムとベース。曲のテンポ（BPM）に合わせて鳴らす |
| 薄いメロディ | 曲のメロディを、BGMとして薄く流し続ける。ミスしても、曲が分かるようにするため |
| 撃退したとき | そのノーツの音を、薄いメロディより大きく鳴らす（ヒットすると、メロディが目立つ） |
| ミスしたとき | 効果音はない。薄いメロディは流れ続ける |
| 同時に落ちるウイルス | 天国と地獄の一部。それぞれ、自分の音が鳴る |

- AudioContext は、最初の曲の開始操作（キーまたはクリック）のときに作る。

## 8. データ仕様

### 8.1 曲データ（`charts.js` の `SONGS`）

`SONGS` は曲の配列。曲を増やすときは末尾に1つ足す（並びは変えない）。

| 項目 | 内容 |
| --- | --- |
| `name` | 曲名 |
| `star` | 星の数（1〜5） |
| `label` | 難易度ラベル |
| `col` | ラベルの色（例：`'#3fbf7f'`） |
| `lanes` | レーン数（2 または 4） |
| `bpm` | テンポ |
| `fall` | 落下時間（秒） |
| `chart` | 譜面。スペース区切りの「音名:長さ」の並び |
| `chara` | セレクト画面のカードに出すキャラの種類（0：ランサム、1：フィッシング、2：DDoS） |
| `santa` | 省略可。`true` にすると、フィッシングがサンタの帽子になる（カードとプレイ中。6章） |

`chart` の書き方：
- 音名 ＝ ドレミ（C D E F G A B）＋ オクターブの数字。`C4` ＝ 真ん中のド、`G4` ＝ ソ、`C5` ＝ 1オクターブ上のド。`#`は半音上（例：`F#4`）。`R` ＝ 休み。
- 長さ ＝ 拍の数。省略すると1拍。`:2` ＝ 2拍、`:.5` ＝ 半拍。
- 同時に落とす音は `+` でつなぐ（長さは最後に1つ書く）。例）`G4+C4:2` ＝ ソとドを同時に（2拍）。先に書いた音を、メロディとして扱う。
- 例）`C4 C4 G4:2 R` ＝ ド・ド・ソ（2拍）・休み（1拍）。

### 8.2 ランキング（`ranking.js` の `Ranking`）

| 項目 | 仕様 |
| --- | --- |
| 保存先 | LocalStorage。**曲ごとに**キー `yumekawa_hs_0`、`yumekawa_hs_1`、`yumekawa_hs_2`（番号は `SONGS` の何番目か） |
| 件数 | 曲ごとに上位10件（スコア降順） |
| 記録の形 | `{ s: スコア, r: 防衛率(%), at: 登録時刻（ミリ秒、Date.now()）, n: 名前 }`。`n` の初期値は「ななし」 |
| 登録 | プレイ終了時に、名前「ななし」で自動で登録する（HP0で終了した場合も登録する）。10位以内なら、リザルト画面で名前を入れられる【できれば】。決めた名前は `Ranking.setName` で記録に書き込む |
| 名前 | 6文字まで。前後の空白は取り除き、空なら「ななし」。画面に出すときは `textContent` を使う（HTMLとして解釈させない） |
| 表示形式 | リザルト：1行に「順位　名前　◯点　◯%」 |
| 保存できない場合 | 読み込みに失敗したら空として扱い、書き込みに失敗しても無視する。ゲームは最後まで動き、リザルトには今回の記録だけが並ぶ |

### 8.3 本日のトップ

- 「本日」＝ 記録の `at` の日付が、今日の日付と同じこと。
- その曲の今日の記録のうち、スコアが最も高いものを「本日のトップ」とする。なければ「--」。
- タイトル画面を表示するたびに、曲ごとに読み直す。

### 8.4 セキュリティ豆知識（`tips.js` の `TIPS`）【できれば】

- `TIPS` は文字列の配列。1つ40文字くらいまで（2行に収まる長さ）。10個くらいが目安。
- 中学生にも分かる言葉で書く。内容は、IPA（情報処理推進機構）などの信頼できるページで確かめる。
- リザルト画面を表示するたびに、ランダムに1つ選ぶ。

## 9. 非機能仕様

| 項目 | 仕様 |
| --- | --- |
| ブラウザ | Chrome |
| 解像度 | 横1920px（16:9）で余白なし。他の比率では余白が出る。縦サイズは決めず、1920×1080 と 1366×768 でテストする |
| 性能 | 30fps以上を目標とする。描画は `transform` で動かし、ウイルスの数は同時に画面内の分だけに限る |
| 音と判定の同期 | 判定・ミス・ウイルスの位置はすべて Web Audio の時計で計算する |
| 堅牢性 | LocalStorage が使えなくてもゲームは最後まで動く（8.2） |

## 10. 内部構成（部品のつなぎ目）

担当をまたぐ呼び出しは、次の関数だけにする。ここに書いていない関数を、他のファイルから呼ばない。

### 10.1 ファイル間の呼び出し

| 関数・データ | 内容 | 呼ぶ側 → 持つ側 |
| --- | --- | --- |
| `SONGS` | 曲データの配列（8.1） | screens.js、game.js → charts.js |
| `Game.start(k)` | k番目の曲でプレイを始める。準備ができたら、プレイ画面に切り替えてゲームループを開始する | screens.js → game.js |
| `Game.stop()` | プレイを中断する（ループ停止、音停止）。結果は出さない | screens.js → game.js |
| `Game.key(code)` | プレイ中のキー入力（`KeyboardEvent.code`）を渡す。対応するレーンがあれば叩く | screens.js → game.js |
| `Game.onFinish` | ゲーム終了時に game.js が呼ぶ関数。screens.js が中身を設定する | game.js → screens.js |
| `Ranking.add(k, s, r)` | k番目の曲に記録（スコア s、防衛率 r、名前「ななし」）を追加して保存し、追加した記録 `{s, r, at, n}` を返す | screens.js → ranking.js |
| `Ranking.setName(k, at, n)` | 【できれば】k番目の曲の、登録時刻が `at` の記録の名前を `n` にして保存する | screens.js → ranking.js |
| `TIPS` | 【できれば】豆知識の文の配列（8.4） | screens.js → tips.js |
| `Ranking.top10(k)` | k番目の曲の上位10件を、スコアの高い順の配列で返す | screens.js → ranking.js |
| `Ranking.todayTop(k)` | k番目の曲の本日のトップ（記録）を返す。なければ `null` | screens.js → ranking.js |
| `Ranking.reset()` | 全曲の記録を消す | screens.js → ranking.js |
| `Screens.show(name)` | 画面を切り替える（`'title'`／`'select'`／`'play'`／`'result'`） | game.js・自分自身 → screens.js |

### 10.2 ゲーム終了時に渡す結果（`Game.onFinish(result)`）

| 項目 | 内容 |
| --- | --- |
| `k` | 曲の番号 |
| `score` | スコア |
| `hit` | 撃退したノーツ数 |
| `total` | 全ノーツ数 |
| `max` | 最大コンボ |
| `dead` | HPが0で終了したか（`true`／`false`） |
| `rate` | 防衛率（%、四捨五入） |
| `rank` | ランク（`'S'`／`'A'`／`'B'`／`'C'`） |
| `comment` | ランクのコメント（5.7） |

screens.js は、この結果を受け取って、認定証の文字を書き、`Ranking.add` で記録して、`Ranking.top10` でランキングを表示し、リザルト画面に切り替える。今回の記録が10位以内なら、名前の入力欄を出す【できれば】。
