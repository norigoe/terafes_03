## 1. 位置づけ

要件定義書の各要件（F-01〜F-09、O-01〜O-03、非機能要件）を、画面・動作・データの仕様として具体的に書いたものである。要件との対応は11章にまとめた。

## 2. システム構成

| 項目 | 仕様 |
| --- | --- |
| 実行方法 | 展示PCのChromeで `index.html` を開く（完全ローカル。サーバー・DB・外部ファイル不要） |
| 描画 | DOM＋CSS。ゲームの更新ループは `requestAnimationFrame` |
| 音 | Web Audio APIで合成（BGM・効果音とも音声ファイルなし） |
| 入力 | キーボードの1〜4キー（上段の数字キーとテンキーの両方を受け付ける）。ボタンはマウスでも操作できる |
| 保存 | LocalStorage（キー `yumekawa_hs`） |
| 論理画面サイズ | 1067×600 px（16:9）。ウィンドウに合わせて拡大縮小する |

### 2.1 画面の拡大縮小

- 倍率 ＝ min(ウィンドウ幅 ÷ 1067、ウィンドウ高さ ÷ 600)。リサイズのたびに再計算する。
- 1920×1080 のとき倍率は約1.8で、余白なしで全面に表示される。
- 16:9以外では上下または左右に余白が出る。余白の色は濃紫（`#2b1f4a`）。

## 4. 入力仕様

| 画面 | 操作 | 動作 |
| --- | --- | --- |
| タイトル | 1キー／2キー | 初級／上級を開始 |
| タイトル | ボタン／ランキングリセット | クリックで開始。リセットは確認ダイアログの後、全記録を消す |
| プレイ | 1〜4キー | 対応レーンを叩く。初級は1・2のみ有効 |
| プレイ | Esc | 中断してタイトルへ |
| リザルト | Enter／Esc | もう一回／タイトルへ |

- 上段の数字キーとテンキー（`Digit1〜4`、`Numpad1〜4`）を区別せず、同じ操作として扱う。
- キーの押しっぱなし（リピート）は無視する。
- 一時停止はない。Escは中断（プレイ結果は残らない）。

## 5. ゲーム仕様

### 5.1 コース

| 項目 | 初級：甘口ぽっぷ編 | 上級：激辛フィーバー編 |
| --- | --- | --- |
| レーン／キー | 2レーン／1・2 | 4レーン／1〜4 |
| 落下時間（上端→判定リング） | 2.4秒 | 1.35秒 |
| 譜面の長さ | 60秒 | 90秒 |
| BPM | 100 | 140 |
| 配置間隔 | 4分音符 | 8分音符 |
| 配置確率 | 60% | 55% |
| ノーツ数の目安 | 約60 | 約250（同時押しを含む） |
| 準備時間（最初のノーツ到達まで） | 3.0秒 | 約1.7秒 |

### 5.2 譜面の生成

譜面はコースごとの固定シードで生成する。同じコースは毎回同じ譜面になる。

1. 準備時間は「落下時間＋0.3秒」を1拍単位で切り上げた長さとする。
2. 準備時間から（譜面の長さ − 1）秒の間、配置間隔ごとに配置確率で抽選する。
3. レーンは乱数で決める。同じレーンが3回続く場合は隣のレーンへずらす。
4. 上級のみ、12%の確率で同時刻に反対側のレーン（レーン番号＋2）へもう1個置く。
5. ウイルスの種類（3種）は乱数で決める。レーンとは無関係。

### 5.3 判定

基準時刻は Web Audio の時計（`AudioContext.currentTime`）を使う。押したレーンの未処理ノーツのうち、タイミング差が最も小さいものを対象にする。

| 判定 | タイミング差 | 基本点 | 表示色 |
| --- | --- | --- | --- |
| 大優勝！ | 0.06秒未満 | 300 | ピンク |
| 神！ | 0.12秒未満 | 200 | 水色 |
| 超かわよ！ | 0.2秒以内 | 100 | 紫 |
| ざんねん…（ミス） | 到達から0.2秒過ぎても未入力 | 0 | 灰紫 |

0.2秒の範囲外での空打ちにペナルティはない。

### 5.4 ウイルスの動き

- 到達時刻の「落下時間×1.15」前に出現させる。
- 縦位置 ＝ 500 − （到達時刻 − 現在時刻）÷ 落下時間 × 530。到達時刻に判定リング（y=500）へ重なる。
- 撃退またはミスで画面から消す。

### 5.5 スコア・コンボ・HP

| 項目 | 仕様 |
| --- | --- |
| スコア | 基本点 ＋ min(コンボ数, 50) × 2 を加算 |
| コンボ | 撃退で＋1、ミスで0に戻る。最大コンボを記録する |
| サーバーHP | 初期値10。ミス1回で−1 |

### 5.6 ゲーム終了

次のどちらかで終了し、リザルト画面へ移る。

- 譜面の終了時刻（準備時間＋譜面の長さ＋0.5秒）を過ぎた。
- サーバーHPが0になった。

### 5.7 防衛率とランク

防衛率 ＝ 撃退したノーツ数 ÷ 全ノーツ数 × 100（四捨五入）。HPが0で途中終了した場合も、分母は全ノーツ数のままとする。

| ランク | 防衛率 | コメント |
| --- | --- | --- |
| S | 95%以上 | 超大優勝★ |
| A | 85%以上 | 大優勝！ |
| B | 70%以上 | 神！ |
| C | 70%未満 | まだまだかわいい |

## 7. サウンド仕様

すべて Web Audio API で合成する。1拍を4分割したステップ（16分音符）で曲を進め、約0.3秒先まで先読みして鳴らす。

| パート | 仕様 |
| --- | --- |
| キック | 毎拍。サイン波のピッチ下降 |
| ハイハット | 各拍の裏。高域ノイズ |
| スネア風 | 小節内の2拍目・4拍目。ノイズ |
| ベース | 1小節に4回。三角波。4小節ごとに音程が変わる |
| リード | 8分音符ごと。矩形波。ペンタトニック5音から選ぶ |
| 撃退の効果音 | ヒット時に鳴る、レーンごとに高さが違うサイン波（0.15秒） |
| ミスの効果音 | なし |

- AudioContext は、最初のコース開始操作（キーまたはクリック）のときに作る。
- BGMの先読みはゲームループ内で行う。そのため、タブが非表示になるとBGMも止まる。

## 8. データ仕様（ランキング）

| 項目 | 仕様 |
| --- | --- |
| 保存先 | LocalStorage、キー `yumekawa_hs`（JSON配列） |
| 件数 | 上位10件（スコア降順） |
| 項目 | `s`：スコア、`d`：コース名、`r`：防衛率(%)、`t`：日時（月日・時分）、`id`：登録時刻 |
| 登録 | プレイ終了時に自動で登録する（HP0で終了した場合も登録する）。名前入力はなし |
| 表示形式 | 「◯点 コース名 ◯% (日時)」 |
| リセット | タイトル画面の「ランキングをリセット」（確認ダイアログあり） |
| 保存できない場合 | 読み込みに失敗したら空として扱い、書き込みに失敗しても無視する。ゲームは最後まで動き、リザルトには今回の記録だけが並ぶ |

## 9. 非機能仕様

| 項目 | 仕様 |
| --- | --- |
| ブラウザ | Chrome |
| 解像度 | 横1920px（16:9）で余白なし。他の比率では余白が出る |
| 性能 | 30fps以上を目標とする。描画は `transform` で動かし、ウイルスの数は同時に画面内の分だけに限る |
| 音と判定の同期 | 判定・ミス・ウイルスの位置はすべて Web Audio の時計で計算する |
| 堅牢性 | LocalStorage が使えなくてもゲームは最後まで動く（8章） |

## 12. 確認事項

1. **操作キーの表記**：要件では「テンキーは使わない（上段の数字キー）」だが、タイトルのサブタイトルに「テンキー連打」が残っている。操作は両方のキーで動く。文言をそのままにするか、直すか決める。
2. **ランキングの範囲**：企画書は「本日」のトップ10。要件定義書と現在の実装は、日付で区切らない上位10件。展示では記録が前日分から残るので、最終日以外はスタッフがリセットする運用になる。
3. **HP0終了時の扱い**：現在は認定証を表示し、ランキングにも登録する。ランキングへの登録をクリア時だけにするかは、要件に記載がないため要確認。
4. **30fpsの確認**：展示PCで実際に計測していない。テスト工程で確認する。
5. **別タブへの切り替え**：切り替え中はゲームループが止まるが、時計は進む。戻った時点で、通り過ぎた分のウイルスが一気にミスになる。展示では起きにくいが、注意が必要。
6. **16:9以外の画面**：展示PCの縦サイズが1080以外だと余白が出る（要件の未決事項と同じ）。
